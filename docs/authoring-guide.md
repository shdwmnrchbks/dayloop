# Pack authoring guide (stub)

A pack is a directory under `/content/packs/<slug>/`:

```
content/packs/p5r/
  pack.json                 # identity, calendar, slots, stats, routes, capabilities
  confidants.json           # bonds + rank-step gates
  activities.json           # repeatable/named activities
  deadlines.json            # palace / exam / missable gates
  answers.json              # exam + class-question answer sheets (optional)
  walkthrough/
    2016-04.json            # default route: one file per month, YYYY-MM.json
    casual/                 # additional routes: one subdirectory per route id
      2016-04.json
  pack-ids.baseline.json    # generated by packlint --write-baseline (do not hand-edit)
```

## Routes (docs/PLAN.md Phase 5)

- `pack.json` may declare `"routes": [{ "id": "casual", "label": "Casual", "description": "…" }]`.
  Pack-supplied labels only — no game terms in Kotlin.
- The **default route** (`standard`) lives at `walkthrough/*.json`; every additional
  route gets its own subdirectory `walkthrough/<routeId>/*.json` with the same
  month-file rules.
- Profiles pin a route (one profile per route/playthrough); the calendar,
  clock, and marks work identically in every route. A subdirectory that is not
  declared in `pack.json` (or a declared route with no files) fails lint.
- Day uniqueness is scoped per route: two routes may author the same date
  differently; one route may not repeat a date.

## Answer sheets (docs/PLAN.md Phase 5)

- `answers.json` carries **facts only**: `id` (`<pack>.answers.exam.<date>` /
  `<pack>.answers.class.<date>`), `date`, `kind` (`exam` | `classQuestion`),
  `label`, `answers` (in asking order; alternates are separate entries), and an
  optional `deadlineRef` into `deadlines.json` for exam sheets.
- Lint cross-checks each sheet against the authored walkthrough: the date must
  have a day, and an `exam` sheet needs a `dayKind: "exam"` day. Class
  questions may also land on days tagged `free` (e.g. Saturday-class weeks).
  Keep walkthrough step labels free of the answers themselves — the sheet is
  the single source of truth.

## Rules enforced by packlint

- Every walkthrough day must exist on the real calendar **with the correct
  weekday** (for `weekdayGrid` packs).
- A day file must only contain days of its own month; no duplicates within a
  route; every day inside the pack calendar range.
- Cross-references resolve: stats, slots, `activityRef`, bond gates,
  `deadlineRef` on answer sheets.
- Bond ranks strictly increase; availability windows parse and stay in range.
- Deadlines need a date or a window, inside the calendar.
- Route directories and declarations must match (see Routes above).
- **IDs are immutable forever** (docs/PLAN.md §3.6): removing or renaming an ID
  that exists in `pack-ids.baseline.json` fails lint. Additions are fine.
  If a removal is genuinely required, regenerate the baseline deliberately
  (`./gradlew packlint "-PpacklintExtra=--write-baseline"`) and say so in the
  commit message.

## Commands

```powershell
.\gradlew.bat packlint                                  # validate default pack
.\gradlew.bat packlint "-Ppack=content/packs/p5r"       # validate a specific pack
.\gradlew.bat packlint "-PpacklintExtra=--write-baseline"
.\gradlew.bat :tools:pack:test                          # schema/lint unit tests
```

## Authoring etiquette

- Steps are short imperatives in **our own words** — never guide prose
  (docs/sources.md).
- `spoiler: true` hides story context behind a tap (docs/PLAN.md §6).
- Coverage warnings are expected while a pack grows; aim to retire them one
  month at a time.

## Mini-packs (schema fit-checks)

- `content/packs/metaphor/` is a **synthetic fit-check, not game content**:
  it exercises the schema's `dayCounter` side (Royal Virtue stat gates,
  non-playable dates, deadline windows) and renders through the same engine
  unmodified. Never treat its labels as game facts.
- `content/packs/p3r/` is real curated data (April 2009 slice from the
  HayateButler guide, docs/sources.md) and will grow into the full pack —
  its IDs are already immutable via its baseline.
- Both packs must keep passing `packlint "-Ppack=content/packs/<slug>"` (CI
  enforces this).
