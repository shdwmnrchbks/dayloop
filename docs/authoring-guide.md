# Pack authoring guide

A pack is a directory under `/content/packs/<slug>/`:

```
content/packs/p5r/
  pack.json                 # identity, calendar, slots, stats, routes, capabilities, labels, theme
  confidants.json           # bonds + rank-step gates
  activities.json           # repeatable/named activities
  deadlines.json            # palace / exam / missable gates
  answers.json              # exam + class-question answer sheets (optional)
  media.json                # graphic manifest: every bundled images/ file + anchors (optional)
  walkthrough/
    2016-04.json            # default route: one file per month, YYYY-MM.json
    casual/                 # additional routes: one subdirectory per route id
      2016-04.json
  art/                      # pack-supplied art, declared via pack.json theme.art slots
    card.png|jpg            # onboarding carousel cover ("card" slot)
    icon.png                # small tiles in Settings ("icon" slot)
  images/                   # pack graphics, declared exactly once in media.json
  pack-ids.baseline.json    # generated by packlint --write-baseline (do not hand-edit)
```

## Routes (docs/PLAN.md Phase 5)

- `pack.json` may declare `"routes": [{ "id": "casual", "label": "Casual", "description": "…" }]`.
  Pack-supplied labels only — no game terms in Kotlin.
- The **default route** (`standard`) lives at `walkthrough/*.json`; every additional
  route gets its own subdirectory `walkthrough/<routeId>/*.json` with the same
  month-file rules.
- Profiles pin a route (one profile per route/playthrough); the calendar,
  clock, and marks work identically in every route. A subdirectory that is not
  declared in `pack.json` (or a declared route with no files) fails lint.
- Day uniqueness is scoped per route: two routes may author the same date
  differently; one route may not repeat a date.

## Answer sheets (docs/PLAN.md Phase 5)

- `answers.json` carries **facts only**: `id` (`<pack>.answers.exam.<date>` /
  `<pack>.answers.class.<date>`), `date`, `kind` (`exam` | `classQuestion`),
  `label`, `answers` (in asking order; alternates are separate entries), and an
  optional `deadlineRef` into `deadlines.json` for exam sheets.
- Lint cross-checks each sheet against the authored walkthrough: the date must
  have a day, and an `exam` sheet needs a `dayKind: "exam"` day. Class
  questions may also land on days tagged `free` (e.g. Saturday-class weeks).
  Keep walkthrough step labels free of the answers themselves — the sheet is
  the single source of truth.

## Theme & vocabulary (docs/ROADMAP-v2.md Phase 10)

`pack.json` may declare an optional `theme` block — the pack's visual identity
(docs/PLAN.md §3.5). The engine maps it to full Material 3 dark/light schemes;
Kotlin contains no game names and no per-game colors.

```json
"theme": {
  "accent": "#A61E22",          // light-scheme seed, "#RRGGBB" or "#AARRGGBB"
  "accentDark": "#D9433C",      // dark-scheme seed (falls back to accent)
  "style": "vibrant",           // tonalSpot | vibrant | expressive | content
  "motif": "masks",             // reserved decorative token (unused today)
  "art": {                      // named art slots, pack-relative paths
    "card": "art/card.jpg",
    "icon": "art/icon.png"
  }
}
```

- **Seeds** — hand-pick `accent`/`accentDark`; the scheme generator derives
  every other role (containers, surfaces, outlines) with guaranteed contrast.
  Pick seeds that represent the pack's mood, not just its logo color.
- **`style`** — closed-set token for how the seed expands: `tonalSpot` (calm,
  default), `vibrant` (bold), `expressive` (playful), `content`
  (source-anchored). packlint rejects unknown tokens.
- **`art` slots** — the engine reads `card` (onboarding hero) and `icon`
  (small tiles); extra slots may be declared for future surfaces and must
  still point at existing png/jpg/jpeg/webp files inside the pack dir.
- **Vocabulary** — `labels.deadlineKinds` renames the closed-set deadline
  kinds the UI prints, e.g. `{ "palace": "Mission" }` for a pack whose
  dungeon deadlines aren't "palaces". Unlisted kinds render as the
  capitalized token. Keys outside the kind set fail lint.

## Media: bundling graphics (docs/ROADMAP-v3.md Phase 11)

A pack may bundle graphics under `images/` (png/jpg/jpeg/webp/gif). Every file
there **must** be declared in `media.json` exactly once, and every declaration
must point at an existing file — orphaned or unresolvable art fails lint, so
"all graphics bundled are served" stays checkable.

```json
{
  "media": [
    {
      "id": "p5r.media.achievement.castle-of-lust-seized",
      "file": "images/img023_CB225A4359DA17EE.png",
      "kind": "achievement",
      "title": "Castle of Lust: Seized",
      "caption": "optional pack-supplied caption",
      "months": ["2016-04"],
      "dates": ["2016-04-30"],
      "bonds": ["p5r.bond.fool"]
    }
  ]
}
```

- `id` — immutable, prefixed `<pack>.media.`, lowercase slug after the prefix.
- `kind` — closed set: `achievement` | `month` | `section` | `day` |
  `portrait` | `banner` | `guide`. The kind decides which surfaces try to
  serve it; it never names a game.
- `title` — required, pack-supplied display text (e.g. the achievement name).
- Anchors are optional and combine: `months` (YYYY-MM keys of the pack's
  calendar), `dates` (ISO dates), `bonds` (bond ids). Unanchored items are
  gallery-only. Anchors are lint-checked: months must be calendar months,
  dates must be calendar dates, bonds must exist in confidants.json.
- Serving today: date anchors render on the Day page, month anchors decorate
  the Calendar header and a month "achievements" strip, bond anchors render a
  portrait on Bond detail; everything is browsable in Settings → Pack media.
- GIFs decode as still first frames today; animated rendering is a Phase 18
  work item (ROADMAP-v3).
- Keep captions in our own words; captions quoting a guide verbatim are
  forbidden by the same rules as prose (docs/sources.md).

## Time models: `weekdayGrid` vs `dayCounter`

- **`weekdayGrid`** (p5r, p3r): the pack omits game-month data and days are
  checked against the **real calendar** — `2016-04-11` must be a Monday.
- **`dayCounter`** (metaphor): the pack declares a game-shaped calendar in
  `pack.json`:
  - `monthLengths`: game-day counts per month (e.g. Metaphor's five 30-day
    months); dates beyond 31 stay valid (`2100-12-35` is representable).
  - `weekdayCycle`: a lowercase-slug in-game weekday list (unique,
    `^[a-z][a-z0-9-]*$`), e.g. Metaphor's 5-day
    `metalsday → idlesday → flamesday → watersday → arboursday` cycle.
  - `weekdayAnchor`: `{ "date": "...", "weekday": "..." }` — one true
    (date, weekday) pair; every other weekday resolves by floorMod from it.
  - `weekdayGrid` and `monthLengths`/`weekdayCycle` are mutually exclusive;
    a cycle without a valid anchor fails lint.
- The engine (`GameCalendar` in `core/pack`) handles both: `next/previous/
  diffDays/indexOf` walk the declared game months, and `weekdayOf` consults
  the cycle (falling back to the real weekday only for grid packs).
- Walkthrough days in a `dayCounter` pack must carry one of the cycle's
  weekday tokens **at the right cycle position** (lint cross-checks).
- Non-playable dates (`calendar.nonPlayableDates`) are excluded from coverage
  and skipped by the progress clock in both models.

## Rules enforced by packlint

- Every walkthrough day must exist on the real calendar **with the correct
  weekday** (for `weekdayGrid` packs).
- A day file must only contain days of its own month; no duplicates within a
  route; every day inside the pack calendar range.
- Cross-references resolve: stats, slots, `activityRef`, bond gates,
  `deadlineRef` on answer sheets.
- Bond ranks strictly increase; availability windows parse and stay in range.
- Deadlines need a date or a window, inside the calendar.
- Media: every `images/` file is declared exactly once in `media.json`; ids,
  kinds, anchors, and files all validate (see Media above).
- Route directories and declarations must match (see Routes above).
- **IDs are immutable forever** (docs/PLAN.md §3.6): removing or renaming an ID
  that exists in `pack-ids.baseline.json` fails lint. Additions are fine.
  If a removal is genuinely required, regenerate the baseline deliberately
  (`./gradlew packlint "-PpacklintExtra=--write-baseline"`) and say so in the
  commit message.

## Commands

```powershell
.\gradlew.bat packlint                                  # validate default pack
.\gradlew.bat packlint "-Ppack=content/packs/p5r"       # validate a specific pack
.\gradlew.bat packlint "-PpacklintExtra=--write-baseline"
.\gradlew.bat :tools:pack:test                          # schema/lint unit tests
```

## Authoring etiquette

- Steps are short imperatives in **our own words** — never guide prose
  (docs/sources.md).
- `spoiler: true` hides story context behind a tap (docs/PLAN.md §6).
- Coverage warnings are expected while a pack grows; aim to retire them one
  month at a time.
